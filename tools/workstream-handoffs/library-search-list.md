# Sources for the author to fetch: running list

**Status:** internal scaffolding, started 2026-11-15 at the author's request. Every session that finds a source it cannot open adds a row here and says exactly what it tried. Sessions remove a row when the source has been read and the claim row closed.

**Rule for adding a row (author, 2026-11-15).** A source goes on this list only after the session has (1) tried the fetch tool, (2) tried a direct download, with his permission where that is needed, (3) looked for a free copy elsewhere (a working paper, an author's page, a government mirror), and (4) written down what happened. "A search did not find it" is not enough. His library time is scarce.

---

## How to hand a source back

1. **An article: download the PDF at the library and attach it to your message in the session.** This is the best form. A link to a library database is no use to a session: it sits behind your login.
2. **A book: photograph the title page, the copyright page, and the pages asked for,** with one page either side so the passage can be read in context. Phone photos are fine if the text is sharp. Attach them the same way.
3. **A free web page that refuses automated visitors** (Part A below): open it at home, use the browser's "Save as PDF" or "Print to PDF," and attach that. Or paste the passage into the message with the page address.
4. **One or two items per message** is easiest to keep straight. Say which row each file answers.
5. **What the session does with it.** It reads the pages, writes a short verification note in `research/citations/` (the passage quoted, page number, edition), closes the row in the claims check, and removes the row here. It does **not** commit the PDF or photos of a copyrighted work to the repository. Only the note with short quotations goes in.
6. **If the library does not hold it,** say so in a word and the row is marked "ask by interlibrary loan" or dropped, whichever you choose.
