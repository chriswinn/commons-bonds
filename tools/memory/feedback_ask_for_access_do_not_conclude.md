# Ask for access; do not conclude a source is missing because one route failed

**From:** the author, 2026-11-15, after reading the Technical Appendix claims check.
**Scope:** every session that checks claims, researches or verifies sources.

**What he said (his words):** "where you didn't already have a permission to access a network you didn't ask me
and just ruled it as forbidden … Please just ask me for permissions if you need to do something you aren't
already allowed to do vs. concluding there is nothing that exists because you can't search."

**What happened.** One host failed to resolve. The session wrote that it was "outside the session's allowed
network" without checking (the environment's network was unrestricted), did not try another copy, and did not
ask. The paper was on the publisher's own archive and was read in a few minutes once tried. Several other
sources were left at "via search; not opened" when opening them was possible.

**How to apply.**
- When a fetch fails, check what kind of failure it is (the environment's network setting, a dead host, a page
  of images, a tool that refuses a site, a permission prompt declined) and say which.
- Try the obvious other routes first: the publisher, a repository record, a different copy.
- If the next step needs something the session is not allowed to do, **ask the author for it by name** (the
  host, the download, the file from his shelf) and carry on with the rest while waiting.
- Never let "could not reach" turn into "no source exists" or "the source disagrees." A status in a claims
  check that rests on an unopened page must say so in the row.

*The reading of "how to apply" is the session's own; the quoted sentence is his.*
